[교통사고 과실비율 검색 시스템 - 1번 담당 인수인계 요약]

1. 구현 완료 범위
- 공통 데이터 스키마 구현
- 과실비율 기준 PDF 3종 파싱
- 심의사례 PDF 파싱
- 도로교통법 PDF 파싱
- JSONL 구조화
- 검색용 facet 청크 생성
- BGE-M3 임베딩
- Chroma 벡터 인덱스 생성
- 기본 Top-K 벡터 검색 구현
- 전체 파이프라인 자동 실행

※ SQLite, BM25, 하이브리드 검색, 리랭킹, 검색 평가는 제외


2. 주요 파일
- schema.py
  공통 데이터 구조와 기본과실 합계 등을 검증

- parse_pdf.py
  MAIN2023, PM2021, ROUND2025 기준 PDF 파싱

- parse_cases.py
  과실비율분쟁 심의사례 파싱
  사례는 참고용이며 기본과실 계산에 직접 사용하지 않음

- parse_law.py
  도로교통법 조문 파싱
  현행 조문과 미시행 조문 구분

- build_chunks.py
  파싱 결과를 검색용 chunks.jsonl과 상세 payloads.json으로 생성
  도표를 요약·상황·해설·수정요소 facet으로 분리

- embedder.py
  hash 및 SentenceTransformer 임베딩 지원
  실제 검색은 BAAI/bge-m3 사용

- build_vector.py
  chunks.jsonl을 임베딩하고 Chroma에 저장

- search.py
  질문을 벡터 검색하고 parent_id 기준으로 결과를 합쳐 Top-K 반환

- build_all.py
  PDF 파싱 → 청킹 → 벡터 생성 전체 자동 실행


3. 데이터 흐름

9. 3번 API 담당 참고
사용 예시

from search import Searcher

s = Searcher()
hits = s.search(query, top_k=5, kind="standard")

주요 반환값
- hit.chunk_id
- hit.score
- hit.facet
- hit.text
- hit.payload

계산 시
- base_ratio 또는 base_ratio_variants 사용
- decision_ratio는 참고 사례 값이므로 기본과실로 사용하지 않음
- 사용자 차량이 A인지 B인지 확인 필요
