------------------------------------------------------------
4-1. schema.py
------------------------------------------------------------

역할
- 파싱 결과의 공통 데이터 계약을 정의합니다.
- Pydantic을 사용하여 기본과실 합계, 수정요소 범위, 필수 필드 등을 검증합니다.

주요 클래스

1) Ratio
- A차량과 B차량의 기본과실 비율을 저장합니다.
- a, b 값은 0~100 범위입니다.
- a + b가 100이 아니면 오류를 발생시킵니다.

예시
{
  "a": 30,
  "b": 70
}

2) Modifier
- 수정요소 1건을 표현합니다.
- target: A 또는 B
- adjustment: 해당 차량 과실에 가감할 값
- condition: 조건 분기
- note_ref: 해설 번호

예시
{
  "name": "현저한 과실",
  "target": "A",
  "adjustment": 10
}

3) Standard
- 기준 도표 1건의 전체 구조입니다.
- standard_id
- source_id
- diagram_no
- section
- title
- party_a
- party_b
- base_ratio
- base_ratio_variants
- modifiers
- accident_description
- base_ratio_explanation
- laws
- precedents
- legacy_nos
- source_page
- book_page
- diagram_image
- parse_flags

생성 파일
- schema.py 자체는 파일을 생성하지 않습니다.
- parse_pdf.py가 추출한 데이터를 검증하고 일정한 형식으로 유지하는 기준으로 사용합니다.

후속 담당자 주의
- 검색 결과 payload의 필드 구조를 변경하려면 schema.py와 build_chunks.py를 함께 확인해야 합니다.
- A/B 방향은 사고유형 기준에서 정의된 차량 역할이므로 사용자 차량과 바로 동일시하면 안 됩니다.


------------------------------------------------------------
4-2. parse_pdf.py
------------------------------------------------------------

역할
- 과실비율 기준 PDF 3종을 파싱합니다.
- 문서별 표기 방식이 다르기 때문에 Profile 구조로 파싱 규칙을 분리했습니다.

지원 문서

1) MAIN2023
- 자동차사고 과실비율 인정기준
- 도표번호 예: 차15-1, 보1, 거2
- 기본과실 예: A30 B70

2) PM2021
- PM 대 자동차 사고 과실비율 비정형 기준
- 도표번호 예: 20. 교차로 부근 사고
- 기본과실 예: A 0 B 100

3) ROUND2025
- 2차로형 회전교차로 사고 과실비율 비정형 기준
- 도표번호 예: 회전-8
- 기본과실 예: 레드20 블루80

주요 기능

1) diagnose
- PDF가 텍스트 기반인지 이미지 위주인지 진단합니다.
- 페이지별 텍스트 길이와 이미지 개수를 확인합니다.

실행 예시
python parse_pdf.py diagnose "pdf/파일.pdf"

2) index
- 도표 시작 페이지와 도표번호를 찾습니다.
- 목차나 본문 상호참조에 나온 번호를 실제 도표로 잘못 인식하지 않도록
  기본과실 표기가 있는 페이지를 중심으로 판정합니다.

실행 예시
python parse_pdf.py index "pdf/파일.pdf" --source-id MAIN2023

3) extract
- 도표별 제목, A/B 차량 설명, 기본과실, 수정요소, 사고상황, 해설,
  법령, 판례, 출처 페이지 등을 구조화합니다.

실행 예시
python parse_pdf.py extract "pdf/파일.pdf" --source-id MAIN2023

생성 파일

data/interim/MAIN2023_standards.jsonl
data/interim/PM2021_standards.jsonl
data/interim/ROUND2025_standards.jsonl

각 줄
- 기준 도표 1건
- JSON 객체 1개

후속 담당자 주의
- parse_flags가 있는 데이터는 자동 파싱 이상 가능성이 있으므로 검수 대상입니다.
- base_ratio가 없는 도표는 조건별 비율인 base_ratio_variants를 확인해야 할 수 있습니다.
- source_page는 실제 PDF 페이지 번호입니다.
- book_page는 책자에 표시된 페이지 번호입니다.

4-3. parse_cases.py
------------------------------------------------------------

역할
- 자동차사고 과실비율분쟁 심의사례 PDF를 파싱합니다.
- 사례는 기준 계산용 데이터가 아니라 참고용 데이터로 분리합니다.

왜 분리했는가
- 기준의 기본과실과 실제 심의 결정비율이 다를 수 있습니다.
- 사례의 결정비율을 기준 비율처럼 사용하면 과실 계산이 잘못될 수 있습니다.

추출 항목
- case_id
- review_no
- title
- referenced_standard_original
- referenced_standard_current
- mapping_status
- accident_description
- base_ratio
- a_party
- b_party
- decision_ratio
- decision_reason
- key_issues
- source_page
- page_span
- parse_flags

실행 예시
python parse_cases.py "pdf/(최종)과실비율심의사례_(54MB).pdf"

생성 파일

data/interim/CASES_reviews.jsonl

주의
- A가 청구인인지 피청구인지는 사례마다 다릅니다.
- a_party와 b_party를 반드시 함께 확인해야 합니다.
- referenced_standard_current가 비어 있고 mapping_status가 review_required인 경우
  구 기준번호와 현 기준번호 매핑 검수가 필요합니다.
- 사례 결정비율은 상담 계산기의 기본과실로 직접 사용하지 않습니다.

------------------------------------------------------------
4-5. build_chunks.py
------------------------------------------------------------

역할
- 파싱된 JSONL을 검색용 청크와 화면 표시용 payload로 변환합니다.
- 하나의 도표를 통째로 하나의 벡터로 만들지 않고 의미 단위 facet으로 나눕니다.

왜 facet으로 나누었는가
- 하나의 도표에는 제목, 사고 상황, 기본과실 해설, 수정요소가 섞여 있습니다.
- 전체 내용을 하나의 벡터로 만들면 내용이 평균화되어 도표 간 유사도 차이가 작아집니다.
- 질문과 가장 가까운 면을 별도로 검색할 수 있도록 분리했습니다.

부모-자식 구조

부모
- 도표, 사례, 법 조문 1건
- payloads.json에 전체 구조 저장

자식
- 검색용 텍스트 청크
- chunks.jsonl에 저장
- parent_id로 부모와 연결

기준 도표 facet
- 요약
- 상황
- 해설
- 수정요소

심의사례 facet
- 요약
- 상황
- 결정이유

법령 facet
- 전문
- 긴 조문은 항1, 항2, 항3 등으로 분할

청크 필드
- chunk_id
- parent_id
- facet
- kind
- source_id
- text
- meta

실행
python build_chunks.py

입력 파일

data/interim/MAIN2023_standards.jsonl
data/interim/PM2021_standards.jsonl
data/interim/ROUND2025_standards.jsonl
data/interim/CASES_reviews.jsonl
data/interim/ROADLAW_articles.jsonl

생성 파일

1) data/processed/chunks.jsonl
- 임베딩 대상 청크
- 한 줄에 청크 1개
- 현재 정상 생성 기준 약 1,878건
- 파일 크기가 0바이트이면 비정상입니다.

2) data/processed/payloads.json
- 부모 단위 상세 데이터
- search.py가 검색 결과 상세 표시 시 사용합니다.
- 도표번호, 기본과실, 수정요소, 법령, 판례, 페이지, 사고상황 등이 포함됩니다.

주의
- chunks.jsonl과 payloads.json은 서로 한 세트입니다.
- build_chunks.py를 다시 실행하면 두 파일이 새로 생성됩니다.
- 검색용 text에는 image_path를 넣지 않습니다.
- 검색 성능 담당자는 chunks.jsonl의 text와 meta를 사용할 수 있습니다.


------------------------------------------------------------
4-6. embedder.py
------------------------------------------------------------

역할
- 임베딩 백엔드를 공통 인터페이스로 제공합니다.

지원 백엔드

1) hash
- 문자 3-gram 해싱 방식
- 모델 다운로드 없이 작동
- 파이프라인 연결 확인용
- 의미 검색용 최종 모델로 사용하면 안 됩니다.

2) st
- SentenceTransformer 기반
- 기본 모델: BAAI/bge-m3
- 운영 및 성능 평가용
- GPU가 있으면 자동으로 CUDA 사용
- CUDA 환경 기본 batch=32

환경변수

EMBEDDING_BACKEND
- hash 또는 st

EMBEDDING_MODEL
- 예: BAAI/bge-m3

EMBEDDING_DEVICE
- cuda 또는 cpu
- 미설정 시 자동 판정

EMBEDDING_BATCH
- GPU 메모리 부족 시 16, 8 등으로 낮출 수 있습니다.

사용 예시

CMD
set EMBEDDING_BACKEND=st
set EMBEDDING_MODEL=BAAI/bge-m3
set EMBEDDING_BATCH=32

중요
- 인덱스를 만들 때와 검색할 때 반드시 같은 임베딩 백엔드와 모델을 사용해야 합니다.
- BAAI/bge-m3 출력 차원은 1024입니다.
- normalize_embeddings=True로 L2 정규화된 벡터를 생성합니다.


------------------------------------------------------------
4-7. build_vector.py
------------------------------------------------------------

역할
- chunks.jsonl의 모든 검색용 텍스트를 임베딩합니다.
- Chroma PersistentClient에 저장합니다.
- 기존 fault_ratio 컬렉션이 있으면 삭제 후 새로 생성합니다.

입력 파일

data/processed/chunks.jsonl
data/processed/payloads.json

실행

CMD
set EMBEDDING_BACKEND=st
set EMBEDDING_MODEL=BAAI/bge-m3
python build_vector.py

처리 과정

1) chunks.jsonl 로드
2) embedder.py에서 임베더 생성
3) 모든 text 임베딩
4) data/processed/vector_index 폴더 생성
5) Chroma PersistentClient 연결
6) 기존 fault_ratio 컬렉션 삭제
7) cosine 공간 컬렉션 생성
8) chunk_id, document, embedding, metadata 저장

생성 결과

data/processed/vector_index/

정상 출력 예시

임베딩 백엔드: st:BAAI/bge-m3 (dim=1024)
1878건 임베딩 중...
완료: ...\data\processed\vector_index | 1878건

컬렉션 정보
- collection name: fault_ratio
- distance: cosine
- metadata에 embedder 이름과 차원을 저장

주의
- chunks.jsonl 크기가 0이면 임베딩할 데이터가 없습니다.
- vector_index를 다른 경로로 복사하거나 강제 이동한 뒤 버전이 달라지면 HNSW 로딩 오류가 날 수 있습니다.
- 인덱스가 손상되거나 로딩 오류가 발생하면 vector_index 폴더를 삭제하고 build_vector.py를 다시 실행합니다.
- Windows에서 한글 경로보다 영문 경로 사용을 권장합니다.


------------------------------------------------------------
4-8. search.py
------------------------------------------------------------

역할
- 기본 벡터 검색을 수행합니다.
- 담당 범위는 질문을 넣었을 때 후보 도표를 반환하는 것까지입니다.

실행 예시

CMD
set EMBEDDING_BACKEND=st
set EMBEDDING_MODEL=BAAI/bge-m3
python search.py "뒤에서 추돌당했습니다"

검색 흐름

1) Chroma PersistentClient 연결
2) fault_ratio 컬렉션 로드
3) 질문을 동일 임베더로 벡터화
4) Chroma query 실행
5) facet 단위 후보를 넓게 조회
6) parent_id 기준으로 부모 도표 단위 통합
7) 부모별 가장 높은 facet 점수를 대표 점수로 사용
8) Top-K 정렬 후 출력

기본값
- top_k=5
- kind="standard"
- 기준 도표만 기본 검색
- source_id 필터 가능

검색 결과 Hit 필드
- chunk_id: 부모 ID
- score: 유사도
- kind: standard, case, law
- text: 최고 점수 facet의 원문
- payload: 부모 상세 정보
- facet: 최고 점수 facet 이름
- facets: facet별 점수

점수 계산
- Chroma cosine distance를 1 - distance로 변환
- 확률이 아니라 벡터 유사도 점수입니다.

현재 정상 검색 예시

질문
뒤에서 추돌당했습니다

1위
차41-1 양 차량 주행 중 후방 추돌
A100:B0

의미
- 1위 후보는 정상적으로 잡힙니다.
- 짧은 질문은 사고 조건이 부족하므로 2~5위에 다른 선행/후행 사고가 섞일 수 있습니다.
- 이를 개선하는 하이브리드 검색, 리랭킹, 검색 평가 기능은 2번 담당 범위입니다.

사용 예시

Python
from search import Searcher

s = Searcher()

hits = s.search(
    "신호대기 중 정차해 있었는데 뒤차가 후면을 추돌했습니다",
    top_k=5,
    kind="standard",
    source_id="MAIN2023",
)

for hit in hits:
    print(hit.chunk_id, hit.score, hit.facet)

법령 조회
- laws_for(article_nos)를 통해 도표 payload의 laws 목록에 해당하는 조문을 직접 조회할 수 있습니다.

1번 담당자가 제공하는 것
- 구조화된 기준 데이터
- 구조화된 심의사례 데이터

2번 담당자가 이어서 구현할 것

1) 키워드 검색
- BM25 또는 형태소 기반 검색
- chunks.jsonl의 text 사용 가능

2) 하이브리드 검색
- BM25 점수 + 벡터 점수 결합
- RRF 또는 정규화 가중합 사용 가능

3) 메타데이터 필터 고도화
- kind
- source_id
- party_prefix
- has_base_ratio
- review_no
- article_no
- in_force

4) 리랭킹
- 벡터 검색 상위 20~50개 후보를 Cross Encoder로 재정렬
- 예: BAAI/bge-reranker-v2-m3

5) 성능 평가
- 팀 공통 검색 질문 20개 이상
- 정답 도표 ID 또는 정답 후보 집합 지정
- Top-1 Accuracy
- Top-3 Accuracy
- MRR

6) 유사 판례 검색
- Searcher.search(..., kind="case")
- 사례는 참고용이며 계산에 직접 사용하지 않도록 표시

7) 관련 법령 검색
- Searcher.search(..., kind="law")
- 또는 도표 payload의 laws 목록을 Searcher.laws_for()로 직접 조회

8) 검색 실패 및 범위 밖 판정
- 최고 점수 임계값
- 1위와 2위 점수 차이
- 필수 사고조건 누락
- 범위 밖 키워드
- 검색 결과 없음

중요
- 1번 담당 코드의 search.py는 기본 벡터 검색 기준선입니다.
- search.py 자체를 무리하게 수정하기보다 새 파일을 만드는 방식을 권장합니다.
