■ 한눈에 요약
------------------------------------------------------------------------
CV 영상분석 파트
- 코드: 9개 파일, 약 722줄 (services/cv 6개 + train 3개)
- 데이터 처리: CCD 사고영상 1,500개 전부 처리
- 성능: 사고 여부 판단 F1 0.921, 정밀도 1.000(오탐 0)
-  → 전부 신규 작성


■ 이 파트가 하는 일
------------------------------------------------------------------------
사용자가 올린 dashcam 영상에서 "사고 순간"을 찾아,
그 전후 프레임을 YOLO 박스 그려서 뽑아준다.
이 프레임이 화면 표시 + LLM(Gemini) 입력이 된다.


■ 만든 파일 (9개)
------------------------------------------------------------------------
[services/cv/ — 실제 서비스 로직]
- detect.py       YOLO 차/사람 검출 래퍼
- track.py        ByteTrack 추적 (프레임 간 객체 연결)
- trajectory.py   추적 → feature 6종(IoU·속도·가속도 등) 계산
- collision.py    규칙으로 사고 순간 판단
- extract.py      사고 전후 프레임 추출 + YOLO 박스 그리기 (화면·LLM용)
- ccd_labels.py   CCD 정답파일 파서

[train/ — 데이터 처리·튜닝·평가]
- prepare_ccd.py     CCD 영상 1500개 → feature+정답 데이터 생성
- tune_collision.py  CCD 정답으로 임계값 자동 튜닝 + 성능 채점
- diagnose_ccd.py    감지 성능 원인 진단


■ 한 작업 (코드 작성 외)
------------------------------------------------------------------------
- CCD 데이터셋 영상 1,500개를 YOLO로 전부 돌려 feature 추출
  (GPU로 처리, 결과 ccd_features.npz 생성)
- CCD 정답(binlabels)으로 사고 감지 임계값을 자동 튜닝
- 감지 성능 측정: F1 0.921 / 정밀도 1.000 / 재현율 0.854
- 성능이 낮은 부분(사고 순간 적중)의 원인까지 진단
  (CCD 라벨=사고 시작 vs 우리 예측=충돌 정점 어긋남을 데이터로 규명)


■ 내가 내린 설계 결정
------------------------------------------------------------------------
- 사고 감지를 딥러닝 대신 규칙 기반으로 채택
  (근거: 과실 판단은 LLM이 하므로 감지만 하면 됨. 규칙은 과적합 위험 없음)
- 임계값을 손으로 안 정하고 CCD 데이터로 자동 튜닝하게 설계
- 1인칭 dashcam 시점으로 통일 (학습·검증 시점 일치)
- LLM을 Gemini로 결정
  (업스테이지 Solar는 문서 전용 비전이라 사고 장면 사진을 못 읽음을 확인)
