### EXP-1 · 평가셋 정정 (검색 알고리즘 변경 없음)

> ⚠️ **이건 검색이 좋아진 게 아니라 "잘못 세던 것"을 고친 것입니다.**
> 인덱스·모델·검색 코드 전부 EXP-0과 동일합니다. **개선폭 계산의 기준선은 이 수치입니다.**

| 지표 | EXP-0 (라벨 오류 포함) | EXP-1 (정정) |
|---|---:|---:|
| Top-1 | 46.7% (7/15) | **64.3%** (9/14) |
| Top-3 | 60.0% (9/15) | **78.6%** (11/14) |
| Top-10 | 86.7% (13/15) | 85.7% (12/14) |
| MRR | 0.573 | **0.717** |
| 오답 방지 | 0/5 | 0/6 |

#### 무엇을 고쳤나

**① 복수 정답 지원** — `gold_id` 에 `;` 로 여러 개를 적을 수 있게 `evaluate.py` 를 확장했습니다.
기준서에는 **질문만으로 구분 불가능한 도표 쌍**이 있어서, 하나만 정답으로 두면 맞는 답을 오답으로 셉니다.

| 문항 | 기존 정답 | 정정 | 근거 |
|---|---|---|---|
| 빨간불에 길을 건너다가 차에 치였습니다 | `보1` | `보1;보2` | **제목이 글자 그대로 동일.** 자동차 신호(녹색/황색)만 다른데 질문에 그 정보가 없음 |
| 킥보드로 자전거횡단도 건너다가 자동차에 치였습니다 | `PM2021-20` | `PM2021-20;PM2021-25` | `20`은 "교차로 부근" 조건이 붙는데 질문에 없음. `25`가 오히려 더 정확. 기본과실도 둘 다 A0:B100 |

**② "정보부족"인데 정답이 박힌 문항 제거**

```
사거리에서 좌회전하다가 사고났습니다   →  gold_id 비움 (정보부족)
```
신호 유무·상대 진행방향이 없어 도표를 특정할 수 없습니다. 그대로 두면 **Top-3와 오답 방지율이 서로 싸웁니다** —
임계값을 올려 거절하면 Top-3가 깎이고, 답하게 하면 오답 방지가 안 오릅니다. **되묻기 대상**이 맞습니다.

#### Top-10만 내려간 이유

`13/15 → 12/14`. 빠진 문항(`사거리에서 좌회전…`)이 마침 **9위로 Top-10 안에 있었기** 때문입니다.
분자·분모가 각각 1씩 줄어든 것이고 검색 성능 변화가 아닙니다.

### 참고 · 파싱 수정 전후 (같은 조건, 데이터만 다름)

파서 버그 2건(#4 보N 당사자 오배정, #5 해설 누락·오염)을 고치고 재인덱싱한 결과입니다.
**검색 알고리즘은 동일**하고 데이터만 바뀌었습니다.

| 지표 | 수정 전 (1,878청크) | 수정 후 (1,945청크) |
|---|---:|---:|
| Top-1 | 40.0% | **46.7%** ↑ |
| Top-3 | 66.7% | 60.0% ↓ |
| Top-10 | 80.0% | **86.7%** ↑ |
| MRR | 0.550 | **0.573** ↑ |

**Top-3만 떨어진 것처럼 보이는데, 실제로는 10건 → 9건입니다(1건 차이).**
15문항짜리 평가셋에서 1건은 6.7%p라 지표가 크게 흔들립니다. 4개 지표 중 3개가 올랐고,
아래 개별 변화를 보면 데이터 품질은 분명히 좋아졌습니다.

#### 개별 순위 변화

| 질문 | 전 | 후 | |
|---|---:|---:|---|
| 횡단보도 근처에서 길 건너다가 차에 치였어요 | 권외 | **1위** | ✅ 개선 |
| 뒤에서 오던 차가 제 차를 들이받았어요 | 2 | 3 | |
| 빨간불에 길을 건너다가 차에 치였습니다 | 2 | 5 | |
| 신호없는 교차로에서 차선 바꾸다가 우회전 차와 접촉 | 4 | 5 | |
| 킥보드로 자전거횡단도 건너다가 자동차에 치였습니다 | 3 | 4 | |
| 사거리에서 좌회전하다가 사고났습니다 | 6 | 9 | |
| (나머지 9건) | — | — | 변동 없음 |

#### 왜 이렇게 움직였나

**개선** — `보20`("횡단보도 부근 보행자 횡단")은 수정 전 `사고 상황`이 **비어 있어서** 검색 경쟁에
아예 못 나왔습니다. 이제 51자 설명이 채워져 **점수 0.7493으로 1위**가 됐습니다.
버그 #5를 고친 직접적 효과입니다.

**후퇴** — 사고상황이 194건 → 228건으로 늘면서 **경쟁 후보가 34건 증가**했습니다.
전에는 설명이 없어 랭킹에 못 오던 도표들이 이제 올라오면서 정답을 한두 칸씩 밀어냈습니다.
데이터가 완전해진 결과이지 검색이 나빠진 게 아닙니다.

### EXP-2 · BM25 단독 (문자 2~3-gram)

| 설정 | 값 |
|---|---|
| 토크나이저 | 어절 + 문자 2·3-gram (`taek/bm25.py`) |
| 랭커 | `rank_bm25.BM25Okapi` (기본 k1·b) |
| 색인 단위 | 면(facet) 1,945개 — 벡터와 동일 |

| 지표 | 벡터 (EXP-1) | **BM25** |
|---|---:|---:|
| Top-1 | 64.3% | 50.0% |
| Top-3 | **78.6%** | 57.1% |
| Top-10 | 85.7% | 71.4% |
| MRR | **0.717** | 0.554 |

**단독으로는 벡터가 확실히 낫습니다.** 예상대로입니다.

#### 🚨 그런데 하이브리드의 상한이 벡터와 같습니다

| 질문 | 벡터 | BM25 | |
|---|---:|---:|---|
| 뒤에서 오던 차가 제 차를 들이받았어요 | 3 | 권외 | 벡터만 |
| 신호 없는 사거리에서 직진하는데 맞은편에서 좌회전 | 1 | 2 | |
| 빨간불에 직진했는데 좌회전 화살표 신호받은 차와 충돌 | 1 | 1 | |
| 빨간불에 길을 건너다가 차에 치였습니다 | 1 | 권외 | 벡터만 |
| 주차장 통로로 가는데 주차칸에서 차가 나오다 | 1 | 1 | |
| 추월금지구간에서 뒤차가 저를 앞질러 들어오다 | 2 | **1** | BM25가 더 잘함 |
| 반대편 차가 중앙선 넘어 유턴하다가 | 1 | 1 | |
| 아파트에서 후진하는 차 뒤를 지나가다 | 1 | 1 | |
| 신호없는 교차로에서 **차선 바꾸다가** 우회전 차와 접촉 | 5 | 권외 | ❌ 둘 다 실패 |
| 회전교차로 안에서 두 차가 동시에 들어오다 | 1 | 1 | |
| **전동킥보드로** 직진하는데 신호없는 교차로에서 | 권외 | 9 | ❌ 둘 다 실패 |
| 킥보드로 자전거횡단도 건너다가 | 1 | 1 | |
| 2차로 회전교차로에서 … 새로 들어온 차가 **차선 바꾸다** | 권외 | 권외 | ❌ 둘 다 실패 |
| 횡단보도 근처에서 길 건너다가 | 1 | 7 | 벡터만 |

```
Top-3   벡터 11/14 (78.6%)   BM25 8/14 (57.1%)
둘 중 하나라도 Top-3 성공  =  11/14 (78.6%)   ← 벡터 단독과 동일
```

**BM25가 Top-3에서 새로 살려내는 문항이 하나도 없습니다.**
BM25가 이긴 유일한 문항(`추월금지구간…` 2위→1위)도 이미 벡터가 Top-3 안에 넣은 것입니다.

→ **RRF·가중합을 아무리 잘 튜닝해도 이 평가셋의 Top-3는 78.6%를 못 넘습니다.**
   결합 방식의 문제가 아니라 **두 방식이 같은 문항에서 함께 실패**하기 때문입니다.

#### 실패 3건의 공통 원인은 랭킹이 아니라 어휘였습니다

| 사용자 표현 | 코퍼스 등장 | 문서가 쓰는 말 | 등장 |
|---|---:|---|---:|
| `차선` | **8** | `차로` | 943 |
| `차선 바꾸다` | — | `진로변경` | 155 |
| | | `차로변경` | 32 |
| `킥보드` | **0** | `PM` | 56 |
| | | `개인형 이동장치` | 20 |

실패한 3건이 전부 이 두 어휘에 걸립니다.

- `신호없는 교차로에서 **차선 바꾸다가**` → 문서는 `진로변경`
- `**전동킥보드**로 직진하는데` → 문서는 `PM`
- `2차로 회전교차로 … **차선 바꾸다**` → 문서는 `차로변경`

**없는 단어는 임베딩도 BM25도 못 찾습니다.** 문자 n-gram이 조사 변형은 흡수하지만
`차선 ↔ 차로`, `킥보드 ↔ PM` 같은 **다른 낱말**은 못 잇습니다.

#### 그래서 계획을 바꿉니다

| | 기존 우선순위 | 수정 |
|---|---|---|
| 하이브리드(EXP-3·4) | 최우선 | **유지하되 기대치 하향** — Top-3 개선 없음. MRR·Top-10과 발표 근거로는 여전히 가치 있음 |
| 동의어/질의확장(EXP-8) | 나중에 | **최우선으로 승격** — 실패 3건을 모두 겨냥 |
| 평가셋 확장(EXP-1b) | 요청 필요 | **더 시급해짐** — 14문항으로는 위 결론도 잠정입니다 |

> ⚠️ 위 분석은 **14문항 기준**입니다. 1문항이 7.1%p를 움직이므로
> "하이브리드가 무의미하다"가 아니라 **"이 14문항으로는 차이를 볼 수 없다"** 가 정확한 표현입니다.

## ⚠️ 평가셋의 알려진 문제

### ~~1. 정답이 하나뿐이라 "동등하게 맞는 답"이 오답 처리됨~~ → EXP-1에서 해결
### ~~2. "정보부족"인데 정답이 박힌 문항~~ → EXP-1에서 해결

### 3. 평가셋이 너무 작음

정답 있음 15문항(중복 제외 시 실질 14개 도표)입니다. **1문항이 6.7%p**를 움직여서,
하이브리드로 2~3건 개선된 걸 우연과 구분할 수 없습니다.

→ 공통 업무가 *"각자 검색 질문 20개 작성"* 이므로 **1·3·4번에게 수집 요청**. 목표 60~80문항.

### 4. 질문 어휘와 문서 어휘가 어긋남 ★ 검색으로는 못 푸는 실패

`전동킥보드로 직진하는데 신호없는 교차로에서 좌회전 차가 들이받았어요` 는 **Top-10 밖**입니다.
상위에는 자전거 도표(`거8-1`, `거10-3` …)만 올라옵니다.

코퍼스 어휘를 세어 보면 이유가 분명합니다.

| 표현 | 포함 청크 수 |
|---|---:|
| `킥보드` | **0** |
| `전동` | 6 |
| `개인형 이동장치` | 20 |
| `PM` | 56 |

**사용자가 쓰는 말("킥보드")이 문서에 한 번도 안 나옵니다.**
임베딩도 BM25도 없는 단어를 매칭할 수는 없습니다. → **동의어 사전 / 질의 확장**이 필요합니다.

```
킥보드 · 전동킥보드 · 씽씽이  →  PM · 개인형 이동장치
```

EXP-2(BM25)로도 안 풀리는 항목이므로 **별도 실험(EXP-8)** 으로 잡습니다.

### 설계 메모

- **BM25 토크나이저**: `rank_bm25` 는 토크나이저를 제공하지 않습니다. 공백 분리만 하면
  `교차로에서` ≠ `교차로` 라 조사 때문에 성능이 안 나옵니다. 형태소 분석기는 Windows 설치 비용이 크므로
  **문자 2~3-gram**으로 갑니다.
- **점수 결합**: 코사인(0~1)과 BM25(0~수십)는 스케일이 달라 단순 가중합이 안 됩니다.
  **RRF를 기본**으로, 정규화 가중합을 비교군으로 둡니다.
- **결합 단위**: 벡터 검색이 **자식(면) 단위 → `parent_id` 병합**이므로 BM25도 **같은 면 단위**로
  인덱싱해야 두 랭킹이 맞물립니다.
- **메타 필터**: `section` 은 57개 절이 도표 번호 순서대로 묶여 있어 필터 축으로 쓸 수 있습니다.
