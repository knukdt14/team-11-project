| 지표 | 값 |

| Top-3 | 36/64 · **56.2%** |
| Top-10 | 50/64 · 78.1% |
| MRR | 0.454 |

**BM25가 벡터를 이겼습니다.** 구 평가셋(14문항)에서는 정반대였습니다 — 표본이 작으면 결론이 뒤집힌다는 실례입니다.

#### 상보성 — 하이브리드의 근거

| | 문항 |
|---|---:|
| 벡터만 Top-3 성공 | 9 |
| BM25만 Top-3 성공 | 12 |
| 둘 다 성공 | 24 |
| 둘 다 실패 | 19 |

```
합집합(하이브리드 상한) = 45/64 = 70.3%   ← 벡터 대비 +18.8%p
```

**64문항 중 21문항을 한쪽만 맞힙니다.** 이 구조가 뒤에 나오는 `k` 선택의 근거가 됩니다.

패턴도 뚜렷합니다.

- **BM25 우세** — 회전교차로 계열 4건. `진입`/`회전`/`진출` 처럼 **정확한 낱말**로 도표가 갈리는 영역은 의미 유사도로 뭉개집니다.
- **벡터 우세** — 신호·보행자·자전거 계열. 서술이 풀어져 있는 질문입니다.

### EXP-3 / EXP-4 · 융합

`python -m taek.sweep` 전체 결과는 `results/sweep_base.md`.

| 설정 | Top-1 | Top-3 | Top-10 | MRR |
|---|---:|---:|---:|---:|
| 벡터 단독 | 32.8% | 51.6% | 73.4% | 0.447 |
| BM25 단독 | 29.7% | 56.2% | 78.1% | 0.454 |
| **RRF k=1** | **39.1%** | **60.9%** | **84.4%** | **0.526** |
| RRF k=10 | 35.9% | 59.4% | 85.9% | 0.502 |
| RRF k=60 (관례값) | 35.9% | 53.1% | 79.7% | 0.488 |
| 가중합 α=0.3 | 34.4% | 59.4% | 78.1% | 0.484 |
| 가중합 α=0.5 | 35.9% | 51.6% | 84.4% | 0.495 |

**RRF k=1 이 전 지표 1등.** 벡터 대비 Top-3 **+9.3%p**, Top-10 **+11.0%p**, MRR **+0.079**.

#### 가중합을 안 쓰는 이유

α를 0.2~0.8로 훑어도 Top-3가 51.6~59.4% 사이에서 **단조롭지 않게 튑니다.**
질의마다 점수 분포가 달라 min-max 정규화가 흔들리기 때문입니다.
RRF는 순위만 쓰므로 스케일 문제가 없고 조절할 값이 `k` 하나뿐입니다.

#### ⭐ 왜 관례값 60이 아니라 1인가

```
k=60 :  1/61=0.0164  1/62=0.0161  1/63=0.0159   ← 거의 평평 → "합의 투표"
k=1  :  1/2 =0.500   1/3 =0.333   1/4 =0.250    ← 가파름   → "가장 잘 맞힌 쪽을 믿음"
```

원논문(Cormack 2009)의 60은 **TREC에서 수십 개의 잡음 있는 검색 결과를 융합**할 때
합의로 잡음을 거르는 값입니다.

우리는 검색기가 **2개**이고 **21/64 문항을 한쪽만** 맞힙니다.
합의를 중시하면 그 21문항을 스스로 눌러버립니다. **곡선 맞추기가 아니라 데이터 구조에서 나온 결과**입니다.

> 다만 `k=1` 이면 원논문의 감쇠 의도가 거의 사라집니다.
> 발표에서는 *"RRF를 쓰되 k를 관례값에서 크게 낮췄고, 이유는 검색기가 2개이고 상보성이 크기 때문"* 이라고
> 설명하는 것이 정확합니다.

### k 선택의 통계 검증 (`validate_k.py`)

**① 낙관 편향은 거의 없습니다**

절반에서 `k`를 고르고 나머지 절반에서 채점하기를 400회 반복:

```
전체에서 고른 최고점    60.9%
반분 선택 후 검증 평균  60.5%
→ 낙관 편향            +0.4%p
```

선택된 `k` 분포: **작은 k 339회 / k=10 53회 / k=5 8회 — k=60 은 0회.**

**② 그러나 유의성은 주장할 수 없습니다**

| 비교 | 재표집 우세 비율 | 차이 95% CI | 판정 |
|---|---:|---|---|
| RRF k=1 > 벡터 | 96.0% | `[+0.0, +18.8]%p` | 0 포함 |
| RRF k=1 > BM25 | 77.2% | `[−6.2, +15.6]%p` | 0 포함 |
| RRF k=1 > k=60 | 90.0% | `[−3.1, +18.8]%p` | 0 포함 |

**64문항으로는 9%p 차이를 유의하게 잡아내지 못합니다.**

> 정직한 표현: *"하이브리드가 Top-3 +9.3%p 높았고 재표집 96%에서 우세했으나,
> 신뢰구간이 0을 포함해 이 표본으로는 유의성을 주장할 수 없다. 문항 확대 후 재검증 필요."*

**③ `k=1` 은 봉우리가 아니라 격자 경계**

```
k=0  62.5%   k=0.5  60.9%   k=1  60.9%   k=2  59.4%
k=5  57.8%   k=10   59.4%   k=20 59.4%   k=60 53.1%
```

`k=0` 이 0.5%p 높지만 **1문항(1.6%) 안쪽 차이**이고 수식이 퇴화합니다.
RRF 형태를 유지하면서 합의 가중을 최소화하는 `k=1` 을 기본값으로 택했습니다.

### EXP-5 · 후보 없음 판정 (거절 임계값)

#### ⚠️ 융합 점수로는 거절 판정을 못 합니다

RRF는 **순위만** 반영합니다. 완전히 엉뚱한 질문이어도 1위는 생기므로 점수가 똑같이 높게 나옵니다.
**유사도를 담은 별도 신호**가 필요합니다.

#### 신호별 분리도

| 신호 | 정답 있음 (평균) | 정답 없음 (평균) | 쓸모 |
|---|---|---|---|
| 벡터 top1 코사인 | 0.693 (0.578~0.798) | 0.583 (0.463~0.694) | 보통 |
| **BM25 top1 점수** | **54.8 (19.7~129.4)** | **17.3 (4.8~36.4)** | **좋음** |
| 벡터 top1−top2 마진 | 0.015 | 0.014 | **신호 없음** |
| RRF top1 | 0.764 | 0.622 | 값이 뭉텅이 |

#### 채택: 두 신호의 AND

```
벡터 top1 < 0.65  AND  BM25 top1 < 30   →  후보 없음
```

| 방식 | 오답 방지 | 잃은 정답 |
|---|---:|---:|
| 벡터 ≥ 0.65 단독 | 14/16 | **8건** |
| BM25 ≥ 30 단독 | 14/16 | **3건** |
| **AND 조합** | **13/16 (81.3%)** | **0건** |

**AND가 압도적인 이유** — 두 신호가 서로 다른 것을 놓칩니다.

- `킥보드로 인도에서 내려와…` (정답 있음) — 코사인 0.578로 낮지만 BM25가 높아 **살아남음**
- `공장에서 지게차에…` (정답 없음) — 코사인 0.643으로 높지만 BM25가 낮아 **걸러짐**

OR로 묶으면 정답 있는 질문이 대량으로 잘립니다.

#### 거절하지 못한 3건 — 이건 정상입니다

```
0.694  사거리에서 좌회전하다가 사고났습니다
0.684  교차로에서 부딪혔습니다
0.643  공장에서 지게차에 부딪혔는데 과실비율이요
```

앞의 둘은 **진짜 교차로 사고인데 정보가 부족한** 질문입니다.
검색 실패가 아니라 **되묻기로 넘겨야 할 대상**입니다 (README §11 `되묻기[]`).

### EXP-8 · 질의 확장 (동의어)

사전은 `taek/synonyms.py`. **실패한 질문이 아니라 코퍼스 빈도**로 만들었습니다(하단 표 참조).

| | Top-1 | Top-3 | Top-10 | MRR | 오답 방지 |
|---|---:|---:|---:|---:|---:|
| 확장 OFF | 39.1% | 60.9% | 82.8% | 0.523 | **81.2%** |
| 확장 ON — 게이트도 확장 질의로 | 43.8% | 65.6% | 85.9% | 0.573 | 75.0% ❌ |
| **확장 ON — 게이트는 원본 질의로** | **42.2%** | **64.1%** | **84.4%** | **0.558** | **81.2%** ✅ |

개선 16건 / 후퇴 10건. 사전이 겨냥한 항목이 정확히 올랐습니다.

```
킥보드 타고 횡단보도를 녹색불에 건너다      9위 → 1위
킥보드가 중앙선을 넘어와서 부딪혔어요        8위 → 1위
오토바이가 인도로 달리다가 우회전 차와       3위 → 1위
전동킥보드로 직진하는데 신호없는 교차로      권외 → 4위
```

#### ⚠️ 거절 게이트는 반드시 원본 질의로 재야 합니다

확장은 문서 어휘를 질의에 덧붙입니다. 그러면 **범위 밖 질문의 BM25 점수까지 같이 올라가**
AND 게이트가 덜 걸립니다(81.2% → 75.0%).

*"이 질문이 우리 범위인가"* 는 **사용자가 실제로 쓴 말**로 판단해야 합니다.
`search.py` 는 확장 시에도 게이트만 원본 질의로 다시 계산합니다.

### EXP-6 · 메타데이터 필터 정책

축은 이미 있었고(`kind`·`source_id`·`diagram_no`·`has_base_ratio`), **언제 거는가**를 정했습니다.

#### ① 계산 불가 도표 제외 (`only_computable`, 기본 ON)

기본과실이 없는 도표 **17개**는 과실비율을 계산할 수 없어 후보로 낼 의미가 없습니다.
평가셋 64문항에서 **정답이 된 적 0건** — 빼도 손실이 없습니다.

#### ② 특수기준 라우팅 (`route`, 기본 ON)

`MAIN2023` 은 일반기준, `PM2021`·`ROUND2025` 는 **특수기준**입니다. 특수기준이 있으면 그쪽이 우선합니다.

| 키워드 | 대상 | 재현 | 오탐 |
|---|---|---:|---:|
| 킥보드·전동킥보드·PM·개인형 이동장치·씽씽이 | PM2021 | 6/6 | **0** |
| 회전교차로·로터리 | ROUND2025 | 4/4 | 2 |
| ~~회전~~ | ROUND2025 | 4/4 | **19** ❌ |

- `회전` 만 쓰면 **좌회전·우회전에 걸려** 오탐이 19건이 됩니다. 반드시 `회전교차로` 로.
- 회전교차로의 오탐 2건은 실제로는 `MAIN2023 차54`(회전교차로 장)라 **실질 오탐이 아닙니다.**
  문서가 아니라 **주제**가 겹치는 것입니다.

**하드 필터가 아니라 부스트입니다.** 해당 문서 전용 랭킹을 하나 더 만들어 RRF 에 함께 넣습니다.
키워드가 잘못 걸려도 일반 랭킹이 살아 있어 결과가 무너지지 않습니다.

### EXP-7 · cross-encoder 리랭킹

`BAAI/bge-reranker-v2-m3` 로 **상위 20개 후보만** 다시 정렬합니다.

#### 상한은 후보 풀의 재현율입니다

리랭킹은 이미 뽑힌 후보의 순서만 바꿉니다. 후보에 정답이 없으면 아무것도 못 합니다.

| 후보 풀 | 재현율 | |
|---:|---:|---|
| 3 | 65.6% | 리랭킹 전 Top-3 |
| 10 | 87.5% | |
| **20** | **92.2%** | ← 채택. 리랭킹의 상한 |
| 30 | 95.3% | 지연 시간이 선형으로 늘어 기각 |

> ⚠️ 이전에 "상한 70.3%"라고 적었던 것은 **융합의 상한**이지 리랭킹의 상한이 아닙니다.

#### 결과

| | Top-1 | Top-3 | Top-10 | MRR | 오답 방지 |
|---|---:|---:|---:|---:|---:|
| 리랭킹 전 | 46.9% | 65.6% | 87.5% | 0.593 | 81.2% |
| **리랭킹 후** | **54.7%** | **79.7%** | **92.2%** | **0.670** | 81.2% |
| 변화 | +7.8%p | **+14.1%p** | +4.7%p | +0.077 | — |

**Top-3 79.7% — 상한 92.2%의 86%까지 도달.**
Top-10 은 92.2%로 상한에 정확히 일치합니다(리랭킹은 후보 밖을 건드리지 않으므로 당연).

#### 설계에서 신경 쓴 것

- **필터링 뒤에 리랭킹** — 어차피 걸러질 후보에 모델을 돌리는 건 낭비입니다.
- **후보 밖은 자르지 않고 뒤에 붙임** — 잘라 버리면 Top-10 같은 깊은 지표가 근거 없이 떨어집니다.
- **점수 입력에 맥락을 채움** — `hit.text` 는 '가장 잘 맞은 면' 하나뿐이라 부족합니다.
  도표 제목 + 사고상황 + 매칭 면을 합쳐 넣습니다.

#### ⚠️ 한 건으로 판단하지 마세요 (기록)

단일 샘플에서 정답이 1위 → 4위로 밀리고 엉뚱한 `PM2021` 문서가 올라와서
"리랭킹이 해롭다"고 판단할 뻔했습니다. **전체로는 Top-3 +14.1%p 개선**이었습니다.

#### 지연 시간 — 채택의 실질적 제약

요청 1건 전체 소요(검색 + 리랭킹), 후보 20개 기준. 모델 로드 시간은 제외(최초 1회).

| 환경 | 리랭킹 OFF | 리랭킹 ON |
|---|---:|---:|
| CPU (`torch 2.13.0+cpu`) | ~0.57s | **6.87s** |
| **GPU (RTX 4070 Laptop, `cu126`)** | **0.098s** | **0.494s** (최대 0.837s) |

**GPU 에서 14배 빠릅니다.** 0.5초면 시연에 쓸 수 있습니다.
CPU 6.87초는 못 씁니다.

그래서 `Searcher` 의 기본값은 **`rerank=False`** 입니다 — GPU 없는 팀원 환경에서
API 가 요청당 7초씩 걸리면 안 되기 때문입니다. 3번이 환경을 보고 켜세요.

## 최종 구성

```bash
python -m taek.evaluate --mode hybrid --reject --expand --rerank
```

`route` 와 `only_computable` 은 기본 ON, `rerank` 는 기본 OFF입니다.

## 알려진 한계

1. **유의성 미확보** — 64문항으로는 9%p 차이를 통계적으로 입증할 수 없습니다. 문항 확대 필요.
2. **하이퍼파라미터를 같은 셋에서 골랐습니다** — 낙관 편향은 +0.4%p로 작지만 0은 아닙니다.
   3·4번 문항이 오면 **`k=1`·임계값을 고정한 채** 다시 재야 합니다.
3. **평가셋 작성자가 1번 한 사람** — 작성자별 편향은 아직 측정 못 했습니다.
   3·4번 문항이 오면 출처별로 나눠 재면 그 차이가 곧 편향의 크기입니다.
4. **상한 70.3% 중 60.9%** — 남은 9.4%p는 한쪽만 맞힌 문항이 3위 밖으로 밀린 경우입니다.
   리랭킹(EXP-7)이 노릴 지점입니다.
